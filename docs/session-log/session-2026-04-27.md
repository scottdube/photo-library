# Session 2026-04-27 — Photos Library Migration to External SSD

## Summary

Migrated the Photos library from the Mac Mini's internal disk to the new external 4TB SSD (Samsung 990 EVO Plus + OWC Express 1M2), switched it to System Photo Library, and flipped iCloud Photos from "Optimize Mac Storage" to "Download Originals to this Mac." Post-migration osxphotos diagnostics confirm the ~1,452 None-filepath gap from session 2026-04-24 is fully resolved: 0 missing photos, 0 blank-path entries against 21,493 photos in the filtered set. Phase 1 indexing is cleared to target the full library.

## Setup

**External storage:** Samsung 990 EVO Plus 4TB (single-sided M.2 2280, NVMe) in OWC Express 1M2 Thunderbolt enclosure. Hardware ordered 2026-04-24, delivered 2026-04-27. Connected via supplied Thunderbolt cable to a back-panel Thunderbolt 4 port on the Mac Mini (front USB-C ports on the M4 are USB 3 only and would have capped throughput at ~10× slower).

**Volume format:** APFS, case-insensitive, GUID Partition Map, named `4TB_Removable`. "Owners enabled: No" (equivalent to "Ignore ownership on this volume" in Get Info — required for clean launchd-context access in Phase 1). Mounted at `/Volumes/4TB_Removable`. Connection reported as PCI-Express in Disk Utility, confirming the Thunderbolt path is active.

**Library destination layout:**

| Path | Purpose |
|---|---|
| `/Volumes/4TB_Removable/Photos/Photos Library.photoslibrary` | Apple Photos library (this session) |
| `/Volumes/4TB_Removable/photo-library/` | Reserved for Phase 1 artifacts: DB, thumbnails, symlinks (not created yet) |

## Methodology

1. Installed the 990 EVO Plus into the OWC Express 1M2 per the enclosure's quick-start.
2. Connected to a back-panel TB4 port on the Mac Mini.
3. Opened Disk Utility, View → Show All Devices, selected the top-level device, Erase as APFS / GUID Partition Map / name `4TB_Removable`.
4. Created `/Volumes/4TB_Removable/Photos/` folder for the library bundle.
5. Fully quit Photos.app.
6. Option-dragged `~/Pictures/Photos Library.photoslibrary` to `/Volumes/4TB_Removable/Photos/` in Finder. Copy completed in well under 2 minutes wallclock (consistent with ~2–3 GB/s sustained on the TB4 path; ~125 GB / 60 s = ~2.1 GB/s).
7. Verified the copy via Get Info on both bundles: byte-identical at 124,472,910,792 bytes (124.79 GB on disk), identical Created date of 2025-03-31 14:58, identical Modified time at the moment of the copy. The original on internal showed a Modified time 23 minutes later, indicating Photos.app or a background process touched it after the copy completed; treated as cosmetic since photo data was unchanged.
8. Option-launched Photos.app and selected the external copy from the Choose Library dialog.
9. Photos → Settings → General → "Use as System Photo Library." Acknowledged the standard "Switching the System Photo Library will turn off iCloud Photos" warning dialog.
10. Photos → Settings → iCloud → re-enabled iCloud Photos, set storage option to **Download Originals to this Mac**.
11. Re-enabled Shared Albums (had been disabled as a side effect of step 9).
12. Verified library state via osxphotos diagnostic queries against the new System Photo Library path.

## Key findings

**The 1,452 None-filepath gap from session 2026-04-24 is closed.** Every photo in the Phase 0 filter set now produces a usable path via osxphotos. Cause of resolution is not definitively known; plausible explanations include (a) 3 days of background iCloud activity downloading originals one at a time, (b) the System Photo Library switch + Download Originals flip resetting the database's missing flags, or (c) Phase 0's "None filepath" condition not being identical to osxphotos's `--missing` flag. Operationally the cause does not matter — the gap is functionally gone and Phase 1 can proceed against the full library.

**Thunderbolt 4 path is performing at hardware spec.** ~125 GB transfer in under 2 minutes implies sustained throughput in the ~2 GB/s range, consistent with the Express 1M2 + 990 EVO Plus combination over TB4. This validates the back-port wiring choice; a front USB 3 port would have capped the same transfer at ~10× slower.

**Library auto-detect on osxphotos resolved cleanly to the moved library.** No `--library` flag is needed for queries; osxphotos picks up "last opened library" / "system library" automatically since the external is now the System Photo Library.

## Known issues

**Original library on internal disk retained as fallback.** The pre-migration copy at `~/Pictures/Photos Library.photoslibrary` is still in place. Plan to verify the external library remains stable for 24–48 hours before deleting the internal copy. Not in Trash yet so disk space is unchanged.

**iCloud Shared Photo Library status not yet inventoried.** Photos has a separate "Shared Library" tab in Settings; we have not checked whether one is configured. Current Phase 0 / Phase 1 query filter uses `--not-shared` (legacy Shared Albums) but does not filter `--shared-library`, so any photos in an iCloud Shared Photo Library would currently be in the indexable set. Not blocking; worth noting before Phase 1 commits to a final filter.

**Minor variance between `--count` (21,493) and default-output line count (21,497).** 4-line discrepancy almost certainly attributable to edited-variant or burst-master duplication in the default output. Not investigated; not blocking; rclip dedupes in any case.

## Decisions

**[DECISION] Library lives at `/Volumes/4TB_Removable/Photos/`, not at the volume root.** Reserves `/Volumes/4TB_Removable/photo-library/` for Phase 1 project artifacts (SQLite DB, thumbnail cache, symlink farm) so Apple-managed and project-managed data stay segregated.

**[DECISION] iCloud Photos set to "Download Originals to this Mac"** rather than "Optimize Mac Storage." Drives full-resolution local availability of every photo for CLIP indexing, which is the project's primary motivating use case. With 4TB available, no disk-pressure reason to keep Optimize on.

**[DECISION] Shared Albums re-enabled** after the System Photo Library switch disabled them. Does not affect indexing scope since the osxphotos `--not-shared` filter already excludes Shared Albums content.

**[DECISION] Retain original library on internal disk for 24–48 hours** as a fallback before deletion. If anything anomalous surfaces during early use of the migrated library, Option-launch back to the internal copy is a free recovery path.

**[DECISION] No further investigation of the 1,452 None-filepath issue.** Closed by current state. If the count regresses in a future session, re-open then.
